# 订阅权重编排

Codex Proxy RS `3.54.x` 插件，要求宿主版本至少为 `3.54.3`。使用管理扩展 v2 和宿主内部 HTTP 分派，无需管理 API Key。

## 安装和使用

1. 在「插件管理」上传 `dist/` 中与服务器平台对应的 `.tar.gz`，确认安装。本地提供的包适用于 Linux x86_64（glibc 2.34 或更新版本）。
2. 打开「订阅权重编排」，选择账号分组和套餐，点击「查询」。默认套餐是 Plus，默认按本期订阅开始时间从早到晚排序，开始时间相同则比较到期时间。
3. 核对订阅开始、到期以及当前和建议权重。取消勾选本次不更新的账号，再点「应用」。也可以选择「到期时间优先」后重新查询。

参与排序的有效订阅从最高权重逐级减 1，完全并列共享权重。范围有多个值时，最低权重留给已到期订阅。例如，最低为 `10`、最高为 `30` 时，排序建议为 `30、29、28…11`，到期订阅建议为 `10`。

如设置「订阅开始满多少天后排序」，未满指定天数且仍有效的账号使用统一权重，不占排序名次。以订阅开始后的实际经过时间为准，每 24 小时算一天。例如订阅于周一 15:00 开始，设置 `3` 天后排序，则周四 15:00 起参与排序。查询失败、所需日期不足、账号停用或不支持订阅查询时，预览显示原因并跳过写入。日期来自 OpenAI 返回的实际订阅周期，显示沿用宿主时区。

预览最长有效 10 分钟。应用前会复核账号快照和有效期，过期、达到排序天数或检测到账号变更时需重新查询。每个权重的账号分批更新，只提交权重字段。若应用中断或部分成功，重新查询即可核对已写入的权重。

账号权重是宿主的全局账号属性，该账号所属的其他分组也会使用新权重。续订后可重新查询并应用。

## 插件设置

| 配置 | 默认值 | 用法 |
| --- | --- | --- |
| `groupIds` | 空 | 限定可选择的分组 ID，空值显示所有启用分组 |
| `planTypes` | `plus` | 可选套餐标识，例如 `plus,pro` |
| `excludedAccountIds` | 空 | 填写预览所显示的完整 `acct_…` ID，例如 `acct_abc123,acct_def456`，排除指定账号。删除 ID 并保存可恢复参与 |
| `minWeight` | `1` | 最低建议权重，已到期订阅使用此值 |
| `maxWeight` | `100` | 排序首位的建议权重，需大于或等于最低权重 |
| `rankingAfterDays` | `0` | 订阅开始后满多少天才参与排序，`0` 表示立即参与 |
| `initialWeight` | 留空 | 未满排序天数的有效订阅统一使用的权重。留空使用最低权重 |

在「订阅权重编排」主页面点击「设置」打开卡片。保存后重新查询，旧预览随设置更新失效。设置保存在宿主的插件实例中，可继续使用之前保存的配置。权重可设为 `1` 到 `100` 的整数，启用天数限制时，统一权重须落在配置的区间内。停用名单支持逗号或换行分隔，名单中的账号会显示「已停用编排」，并跳过订阅查询和权重写入。每次预览也可临时取消勾选账号，保留该次显示的建议值。

## 构建

需要 Rust `1.99.1`、Node.js 24 或更新版本，以及与目标宿主版本匹配的 [`cpr-plugin`](https://github.com/zyycn/codex-proxy-rs/blob/6900da36eedb3099d43c8c9bf5b8b97d82d15688/backend/apps/plugin-cli/README.md)。在此目录运行：

```bash
npm --prefix frontend ci
npm --prefix frontend run build
cargo +1.99.1 test --locked
cargo +1.99.1 build --release --locked --target x86_64-unknown-linux-gnu
cpr-plugin package \
  --manifest plugin.json \
  --binary target/x86_64-unknown-linux-gnu/release/cpr-diaoyong \
  --target x86_64-unknown-linux-gnu \
  --resource-map web=frontend/dist \
  --output-dir dist
```
